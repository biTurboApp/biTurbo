# biTurbo 0.3.0 — Autonomous Memory Runtime

biTurbo 0.3.0 adds local automatic capture with review, autonomous integrity repair, better optional local recall ranking, and Linux/WSL CUDA embeddings. It remains fully local and introduces no breaking MCP changes.

## Highlights

- Generic, Codex, and Claude Code observation sources produce redacted, reviewable memory candidates. Raw transcript bodies are not stored by biTurbo, and transcript access is opt-in per project.
- A persisted integrity auditor checks SQLite, FTS, vectors, journal generations, counters, operations, leases, source checkpoints, and candidate aggregates. Automatic repair is limited to reconstructable derived state.
- The shared startup scheduler resumes overdue work whenever either the desktop app or MCP is running; no permanent daemon is installed.
- Explainable deterministic recall can optionally rerank its top 50 results with a pinned local ONNX cross-encoder. Installation is explicit, offline import is supported, and failures fall back visibly.
- Embedding inference supports `auto`, `cpu`, and `cuda`. CUDA is shipped as a separate Linux x86-64 MCP artifact and documented for WSL2; CPU remains the standard cross-platform build.
- A new Runtime workspace provides a candidate inbox, integrity history and safe repairs, source status, accelerator diagnostics, and reranker controls.

## Compatibility and privacy

All v0.2 MCP tool names, inputs, defaults, and response fields remain available. New operations are additive and use the same persisted supervisor from both Tauri and MCP. Pending candidates are excluded from normal recall until approved.

biTurbo still has no accounts, cloud inference, synchronization, remote telemetry, or background daemon. Encryption at rest remains design-only; local database, index, backup, and model files are not claimed to be encrypted. See [the encryption ADR](../architecture/encryption-at-rest.md).

## Upgrade and rollback

The sequential `user_version` migration uses the v0.2 backup and restoration path. Existing v0.1.5/v0.2 memories, settings, operations, feedback, and indexes are preserved. Index rebuilds occur only when content or model identity requires them.

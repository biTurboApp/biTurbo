# v0.3 Autonomous Memory Runtime

biTurbo v0.3 is a local runtime shared by the desktop application and the MCP
sidecar. Both processes open the same application core and coordinate durable
work through SQLite leases. Neither transport owns maintenance, capture, recall,
or model selection, and no permanent daemon is introduced.

## Domain language

- **Observation**: immutable logical input from an agent or transcript source.
- **Observation source**: configured producer such as MCP, Codex, or Claude Code.
- **Source checkpoint**: opaque source cursor committed after successful intake.
- **Evidence**: bounded, redacted provenance supporting a candidate.
- **Memory candidate**: proposed memory excluded from normal recall.
- **Candidate decision**: approve, edit-and-approve, reject, merge, or defer.
- **Capture policy**: project rules for sources, extraction, and approval.
- **Integrity issue**: typed disagreement between authoritative and derived state.
- **Repair plan**: deterministic set of safe repairs for integrity issues.
- **Maintenance policy**: project schedule and automatic-repair settings.
- **Execution provider**: CPU or CUDA backend used for local inference.
- **Active memory**: durable memory eligible for recall.

## Authority boundaries

SQLite memories, mutation journals, candidate decisions, policies, and source
checkpoints are authoritative. FTS rows, vectors, counters, activity summaries,
recall aggregates, and operation progress are derived and reconstructable.

The runtime may automatically repair derived state. Changes to memory meaning,
including merges, replacements, contradiction resolution, archival, and deletion,
always require an explicit user decision.

## Capture flow and privacy

Raw observations are normalized, redacted, and classified in process memory.
The database transaction stores only a receipt, bounded redacted evidence, any
resulting candidates, and the new source checkpoint. Complete transcripts are
never copied into the biTurbo database. Pending candidates do not participate in
`search` or `recall_for_context`.

Transcript adapters are opt-in, read-only, and checkpointed. The generic API is
idempotent by `(source, external_id, content_hash)`. Ollama is an optional
loopback-only extraction enhancement; deterministic extraction remains the
complete fallback and LLM output can only propose candidates.

## Runtime ownership

Scheduled work is claimed transactionally with a process owner, heartbeat, and
lease expiry. One process performs a given project/task class at a time. If a
process disappears, another desktop or MCP process may claim the expired lease
and resume idempotent work. Overdue maintenance starts the next time either
process is alive.

## Compatibility

v0.3 is additive. Existing Tauri commands, MCP tools, request defaults, response
fields, and synchronous legacy behavior remain supported. New asynchronous work
uses the persisted v0.2 operation supervisor.
